# Web 与局域网专题

## 交互合同

- 左侧用于上传参考图、产品名、卖点、AI 扩写、平台/语言选择和提交。
- 右侧顶部展示当前生成进度/结果，下面是统一历史任务；不再拆分“最近完成”和“最近任务”。
- 参考图最多 5 张，支持缩略图、编号、角色、删除、排序和 AI 扩写勾选；`object-fit: contain` 防止竖图撑坏卡片。
- 未提交参考图以账号为作用域保存在浏览器 IndexedDB；刷新后恢复原始文件、文件名、角色与 AI 扩写勾选状态，退出或切换账号后不得读到其他账号草稿。
- 主页卡片和管理弹层支持单/多图拖入，统一去重、上限和反馈；追加不覆盖，拦截无效/满额投放，不递归文件夹。
- 缩略图可打开大图，显示完整文件名、尺寸和大小；支持前后切换、缩放、适应窗口、方向键及 `Esc`，查看与删除区域分离。
- AI 扩写快照当前图片与文本，关闭弹层后继续；完成后展示识图摘要，结果可编辑回填。少于 3 条卖点时按当前品类补足。
- 成品页支持总览、逐张、拼接预览；长图默认适宽，按钮缩放且滚轮只滚动。下载按套图选择单图和拼接图。
- 套图数量为服务端预设：默认 5+8，轻量 1+2、2+3、3+4；历史、总览和下载按任务实际数量显示，未知预设返回 400。
- 生图比例与数量、清晰度独立选择：默认主图 1:1/详情页 9:16，可选主图 3:4/详情页 9:16。页面摘要、扩写和提交必须保留选择，切换其他参数不得重置；未知比例返回 400。
- 清晰度公开 `720P 预览`、`1K 快速`、`2K 标准`，默认 2K。720P 由供应商 1K 缩小，耗时接近 1K；4K 不展示，未知档位返回 400。
- 生成任务板以任务 API 的 `progress`/`timing` 为准显示阶段、主图/详情页数量、首图耗时、当前并发、限流与质检返工；只要成品目录已有图片就应显示缩略图，不等待最终打包。
- 生成请求必须携带 `X-Idempotency-Key`；前端在网络结果不确定时复用同一键，后端返回原任务，不重复扩写或生图。
- 提交后在 Node 返回任务号前，页面先按当前套图建立临时任务板并显示准确总数；此阶段不允许发送缺少真实任务号的停止请求。
- 同一时间只允许一个顶层商品任务处于接收、提交、排队、运行或取消中；图片层仍使用既定并发策略。
- 活动任务可从任务板停止。取消和整批硬超时会结束子进程树、释放运行槽，并保留已落盘结果为部分完成。
- 内测阶段 `LOCAL_WEB_ACCESS_MODE=off`（也是缺省值），页面隐藏令牌输入框，公司局域网设备可直接使用。
- 鉴权实现未删除；需要恢复时在 `.env` 设置 `LOCAL_WEB_ACCESS_MODE=token` 和 `LOCAL_WEB_ACCESS_TOKEN`。页面读取 `/health` 后才显示令牌输入框，令牌仍只保存在当前浏览器 `sessionStorage`。

## 网络合同

- 普通 React 工作台模式保持原合同，Node 默认监听 `0.0.0.0:8787`，前端开发服务监听局域网地址，`LOCAL_WEB_ACCESS_MODE` 缺省为 `off`。
- 若依管理模式的唯一浏览器入口为 `http://127.0.0.1:8001`：管理员使用根路径，普通用户使用 `http://127.0.0.1:8001/portal/`。Node 监听 `127.0.0.1:8787` 并要求内部令牌，Java 监听 `127.0.0.1:8080`，若依 Vue 前端监听 `127.0.0.1:8001`；原 React 管理工作台只监听内部 `127.0.0.1:8002` 并由 `/workbench/` 提供，用户门户 React 只监听内部 `127.0.0.1:8003` 并由 `/portal/` 提供。
- 管理工作台经 Java `/workbench-api/**` 转发 Node。门户只调用 `/portal-auth/**` 与 `/portal-api/**`，服务端校验任务归属；浏览器不接触 Node 令牌。
- 门户成品由前端携带会话令牌获取并转临时 Blob 地址显示/下载；`/portal-media/**` 只是代理别名，不放宽归属鉴权。
- 成品根目录保持严格白名单，只允许已发布数量的主图/详情页总览与完整长图。
- 远端电脑不能访问自己的 `127.0.0.1:8787`。排障时确认页面 URL、代理、主机防火墙、Windows 网络类型和 VPN 路由。
- 后端提交日志应记录来源地址、Host 和转发来源，先判断“请求没到后端”还是“到达后执行失败”。
- `LOCAL_WEB_ACCESS_MODE=off` 时写接口对私网直接开放；`token` 模式保留原鉴权策略：配置令牌后通过 `Authorization: Bearer` 或 `X-Internal-Token` 传递，未配置令牌时仅允许真实本机来源写入。
- CORS 不使用通配符，只反射同源、本机、转发同主机或 `LOCAL_WEB_ALLOWED_ORIGINS` 中的来源。
- `/health` 返回 `ready`、`busy` 或 `degraded`，并提供活动任务阶段、是否可接单及输入/输出盘剩余 GiB，不返回密钥。

## 稳定性与资源合同

- 默认限制：请求 64 MiB、单图 20 MiB、需求模板 1 MiB、卖点 20000 字、最多 5 张参考图、单图 5000 万像素且边长不超过 16384；都可通过 `.env` 中对应 `LOCAL_WEB_*` 变量下调。
- 生图前检查输入盘和输出盘，默认至少保留 5 GiB；不足时返回 507，不能进入扩写或生图。
- `tasks.json` 使用串行临时文件、同步和原子替换，并维护可恢复备份；启动时把遗留活动状态改为 `interrupted`。
- 门户 API 与生成工作流对任务目录共用“非法字符替换为连字符、空白压缩为连字符”的规范；任务收尾和历史对账同时兼容旧记录的原始目录名与规范目录名，避免已落盘成品因目录别名被误判失败。
- 整批工作流默认硬超时 135 分钟；worker 锁每 15 秒心跳，90 秒无心跳可按过期规则恢复。

## 启动与可移植性

- `scripts/start-web.ps1` 只依赖 PATH 中的 Node.js 24+ 和 pnpm，不允许写死某台电脑的运行时路径。
- Node 编排脚本优先复用启动当前进程的 pnpm 入口，直接运行时再回退到 PATH。
- 新电脑先运行 `corepack enable` 和 `pnpm install --frozen-lockfile`，不要复制其他电脑的 `node_modules`。
- 管理端双击 `启动若依管理后台.cmd`，普通用户双击 `启动用户端.cmd`；两者共用串行、可重复启动入口，分别打开根路径和 `/portal/`，同时双击也不会抢占端口。入口先复用健康服务，后端 JAR 过期时只刷新已核验的 Java 进程；否则启动 Docker 与已有 MySQL/Redis，配置或双容器缺失时调用安全恢复流程。残缺容器或旧库凭据不可读时停止，不猜测或重置数据。管理员密码可用 `复制若依管理员密码.cmd` 复制。
- 若依初始化 SQL 必须通过 `docker cp` 以原始 UTF-8 字节导入容器，不能用 Windows PowerShell 文本管道连接 `mysql`。若旧库菜单文字已保存为问号，运行 `admin/scripts/repair-admin-encoding.ps1`；它会建立临时参考库，只回填匹配的损坏显示文字，不重置账户、密码、任务或素材。
- `start-admin.ps1` 会检查五个服务端口、自动构建过期 JAR 并等待 HTTP 就绪，失败时清理本次进程。`refresh-admin-backend.ps1` 只刷新进程记录中与当前 JAR 匹配的 Java，并在 8080 就绪后更新记录。
- 双击启动器固定调用 Windows PowerShell 5.1，执行策略仅对本次生效。凭据校验区分缺失、不可读、字段错误，端口兼容数字/字符串。启动自动保存 `.local-web/ruoyi/logs/launcher-*.json`，记录账户、路径、状态与错误位置，不保存秘密或异常原文。
- 若 Docker 容器与 DPAPI 文件因换 Windows 账户或基础设施丢失而无法同时启动，可从创建 Docker 引擎的同一 Windows 账户运行 `修复若依本机环境.cmd`。它只会在两个容器均不存在时创建新的本机 MySQL 与 Redis；只剩一个容器或旧容器凭据不可读时安全停止。被替换的不可读 DPAPI 文件会改名备份，脚本不删除客户素材、历史任务或既有容器。

## 若依权限与作图合同

- 后端只提供 `GET /bge/health`、`GET /bge/tasks`、`GET /bge/tasks/{taskId}`、`GET /bge/outputs/{outputId}` 和鉴权图片代理。每个入口都有若依权限注解，DTO 会过滤本机路径、完整日志、完整提示词、令牌和来源地址。
- 管理页面支持商品名和状态筛选、按任务实际数量的进度、任务详情、错误摘要和鉴权缩略图。活动任务每 5 秒刷新，页面隐藏或卸载时停止；Blob 地址和请求会被主动回收。
- `bge_viewer` 只有四项只读 BGE 菜单/权限映射，系统用户管理、通用文件上传下载和作图工作台均会被拒绝。`bge_operator` 只额外拥有进入作图工作台及其受保护作图桥接的权限，不会获得系统管理权限。
- 已登录且拥有 `bge:workbench:use` 的用户可从“生图管理 - 电商作图”使用既有 React 工作台。Java 在 `/workbench-api/**` 读取若依登录 Cookie 并在服务端完成权限判断与内部令牌转发；未登录、只读员和其他角色均不能调用作图接口。
- 普通使用者从 `/portal/` 注册为无若依菜单的 `bge_portal_user`；Java 登记任务归属，并在读取、下载、取消和删除前反查。猜测他人 ID 统一返回“未找到”。
- 用户门户注册和登录的验证码走匿名 `/captchaImage`，不走 `/portal-auth`。若依返回的是原始 JPEG Base64，前端必须规范为 `data:image/jpeg;base64,...` 后才可作为图片地址；注册请求继续携带该次返回的 `uuid` 与用户输入的验证码。
- 门户和管理工作台提交图片时，Spring 已解析的 Multipart 请求必须由 Java 仅按受控字段重组后转发给 Node，不能再转发已被消费的原始输入流；无效上传只返回本地校验错误，Node 必须保持存活。`smoke-admin-integration.ps1` 使用故意无效图片验证此路径，不会触发模型或生图供应商。
- Java 对 Node 的读取请求维持短超时；作图与扩写 Multipart 写请求使用独立的 150 秒超时预算。该预算必须高于 Node 的识图/扩写提交预算，避免 Node 已创建任务但门户提前返回 503，造成任务归属未登记和页面误报失败。
- 官方示例 `/test/user/**` 已移除；Springdoc API 和 Swagger UI 默认关闭；登录页不再预填官方默认口令。首次本机启动只会在数据库仍是官方默认管理员密码时替换为 DPAPI 随机密码，已有人工密码不会被覆盖。
- `admin/scripts/smoke-admin-integration.ps1` 使用临时账号做真实本机权限验收，并在 `finally` 中清理账号、门户归属记录、恢复验证码配置和恢复 Node。它验证只读员拒绝、操作员允许、Cookie 桥接、门户注册/登录、本人案例/成图可读、跨用户任务/成品/图片/下载/取消/删除拒绝和 Node 停机降级，不发起生图。

## 排障顺序

1. 检查一键启动窗口和 `8001`、`8002`、`8003`、`8080`、`8787` 监听。
2. 普通用户从主机访问 `http://127.0.0.1:8001/portal/` 注册或登录；管理员从根路径登录后，再从“生图管理 - 电商作图”进入旧受控工作台。
3. 检查浏览器网络请求和后端提交日志。
4. 检查任务状态文件与输出目录，区分页面轮询问题和生成问题。
5. UI 改动后做桌面/窄屏截图检查，确保无溢出、遮挡和不可见操作。

前端目录另有 `frontend/AGENTS.md`，仅补充持久 UI 决策；它与根路由同时生效。
