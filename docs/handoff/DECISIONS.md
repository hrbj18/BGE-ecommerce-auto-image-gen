# 当前有效决策

## 上下文管理

- 根 `AGENTS.md` 是唯一强制入口；默认读取集合只包含 handoff 索引和当前状态。
- 按生图、Web、模型三个专题路由，禁止把全部历史重新汇总成一份长文。
- 旧接手说明和历次优化指导保留作证据，但不再具有当前规则权威性。
- handoff 只记录当前结论；普通问答、重复监控和聊天过程不更新文档。

## 产品与任务

- 新任务使用时间与随机标识形成唯一目录；老任务目录不批量改名。
- 平台规则和语言规则独立组合，平台不得隐式强制语言。
- 前端“最近完成”和“最近任务”合并为右侧预览下方的统一历史任务区域。
- 用户一次提交即可；重试、补图、并发退让属于内部执行策略。
- 套图数量只允许服务端登记的预设。默认 `standard-5-8` 保持历史兼容；`compact-1-2`、`compact-2-3`、`compact-3-4` 分别用于极速、轻量和核心卖点验证。数量、比例和总览文件由预设统一派生，浏览器不能自由组合。

## 生图架构

- 当前参考图和用户输入高于案例、旧模板和历史提示词。
- 先建立产品事实与分镜，再由创意导演为每张图编译紧凑提示词；禁止向每张图重复注入超长公共模板。
- 逐图任务必须靠前，且包含产品状态、场景、动作/道具、构图、视觉证据、可见文案和去重要求。
- 生成前做确定性合同审核，生成后按结构化分镜审核；单图失败或不合格时定向返工。
- 上游不可用时允许确定性降级，但不得用不合格扩写或占位字段静默进入生图。

## 配置与网络

- 前端通过同源 `/api` 与后端通信，避免局域网客户端访问自己的 `127.0.0.1`。
- 若依融合时以 `http://127.0.0.1:8001` 作为唯一用户入口；原 React 作图工作台固定在回环 `8002`，仅由若依前端 `/workbench/` 代理。作图 API 必须先由 Java 校验若依登录态和 `bge:workbench:use` 权限，再带内部令牌转发 Node，内部令牌绝不发送到浏览器。
- 角色分为只读的 `bge_viewer` 和可进入作图工作台但无系统管理权的 `bge_operator`。用户和角色的创建、分配继续使用若依原生“系统管理 - 用户管理”。
- 普通自助用户不用 `bge_operator`，而是从 `8001/portal/` 注册为无菜单的 `bge_portal_user`。门户任务归属以数据库中的账号—任务关系为唯一持久边界；成品、图片和下载授权每次从该账号已拥有的任务动态反查，不依赖可能包含中文的成品目录名。
- 后端监听所有本地网卡；VPN、防火墙和 Windows 网络类型仍需在实际主机验收。
- API 地址、模型与密钥属于运行配置，不写入 handoff。切换供应商必须通过受控配置，不能硬编码到提示词规则。

## 版本库与发布

- GitHub 仓库默认私有；在素材授权、许可证和公开配置未单独确认前不改为公开。
- Git 只保存源码、规则、测试、空配置样例、脱敏需求模板和抽象案例库；客户输入、历史成品、密钥、日志、缓存和依赖只留本机。
- 每次提交前运行发布审计，CI 在 Windows 上重复类型检查、全量测试、前端构建、handoff 审计和发布集合审计。
- 首次接手必须可离线验证项目合同；初始化不得覆盖已有 `.env`，真实模型调用不属于接手证明，必须另行授权。
