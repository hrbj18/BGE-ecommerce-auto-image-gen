# 生图链路专题

## 当前合同

任务按“产品事实 -> 基础分镜 -> 创意导演 -> 逐图提示词 -> 生成前审核 -> 供应商调度 -> 生成后审核/定向返工 -> 拼接与打包”执行。

产品事实来自本次参考图、原始商品名、用户卖点、确认参数、平台和语言。案例库、旧任务、历史提示词只能提供视觉方法，不能提供商品事实。

英文可见展示名必须由原始名称和识图事实支持。强身份词（例如具体原料或剂型）没有可信证据时使用中性品类名；扩写质量门和生成前审核都会检查名称与识图证据的一致性。

## 逐图要求

- 13 张各有唯一销售角色；用户卖点形成覆盖矩阵。
- 当前画面任务放在提示词前部，公共约束压缩为必要条款。
- 提示词使用结构化长度预算：当前帧执行单和文案/画布/禁用项属于必保留区，可选产品上下文和旧提示词片段按完整行压缩；禁止直接截断完整提示词。
- 每张至少明确：产品是否/如何出场、产品状态、场景、人物/动作/道具、镜头构图、光线材质、可见证据、精确文案、与邻图去重要求。
- “高级、真实、丰富”不是证据。证据必须是可见动作、状态对比、结构近景、真实互动、尺度关系或合理视觉隐喻。
- 平台风格与语言分别注入。Amazon 也可中文，国内平台也可 English；新增营销文案必须全套统一。

## 排障顺序

1. 查看任务的 `任务信息.json`/状态记录，确认产品、平台、语言和参考图属于本次任务。
2. 查看 `creative-plan.json`，确认卖点覆盖、逐图场景和去重是否已经具体。
3. 查看 `prompts.json`，确认逐图任务前置、无历史品类词、长度合理、文案语言正确。
4. 查看审核结果与失败日志，区分提示词合同失败、供应商失败、尺寸异常、视觉审核失败和前端未刷新。
5. 只修真正负责该问题的层；不要用更长公共提示词掩盖分镜或调度缺陷。

## 输出审计与返工

- 视觉审计响应必须覆盖全部预期 `role/index`；记录 `responseItemCount` 与 `matchedItemCount` 便于区分图片失败和协议缺项。
- 审计未返回某张图片时只标记人工复核，不得把协议缺项当作可执行质量失败自动重生。
- 对已经落盘的成品可运行 `npm run audit:output -- --dir <成品目录>`，只调用识图审计，不重新生图。
- 经用户授权后，可追加 `--retry-failed`，仅替换审计确认失败的图片；候选图先通过尺寸/文件质量校验，再覆盖原图，随后重建总览、详情长图、审计文件和压缩包。

## 交付速度合同

- 5 张主图按索引优先进入供应商队列；5 路首发槽位由主图占用，后续空闲槽位立即由详情页补齐。首张主图落盘即发出结构化进度事件，Web 可在最终审核和打包前预览。
- 缺图恢复与可行动的视觉审核返工使用独立的受限并行队列，当前默认各 2 路。视觉返工先生成到候选文件，验证成功后才替换原图。
- 生成器持续报告阶段、完成数、主图/详情页分别完成数、重试、限流与首图耗时；后台质检、返工、拼接和打包不得抹掉已生成预览。

## 修改边界

- 规则文件负责稳定平台/语言约束；品类事实和逐图策略放在代码结构层，不向公共规则堆具体商品示例。
- 修改 `src/openai-image-generator.ts` 前先定位函数与测试，避免无关重构。
- 真实付费生成只有在用户明确要求生成/返工时执行。代码验证优先使用测试和小规模工作流。
- 完成后至少运行相关测试、类型检查；改变 13 图链路时运行全量测试。
