# 当前状态

## 现在可确认

- 套图数量为受控预设：默认 `standard-5-8` 为 5+8，轻量预设为 1+2、2+3、3+4；失败图片只定向补齐。
- 新任务只公开国内通用、国外通用两种平台风格；旧八个平台配置仅供历史任务兼容。平台与语言保持解耦；10 种语言继续可选，新增 8 种复用 English 分镜基线，阿拉伯语执行 RTL，未知值返回 400。
- 生成基线保持主图优先、5 路首发、`5>3>2>1` 退让，缺图恢复和视觉返工各为 2 路。首图落盘即可预览，任务 API 持久化真实进度、重试、限流和质检信息。
- React 作图页只允许 `/workbench/` 或 `/portal/` 运行；Node 写接口强制内部令牌，旧 `off` 配置也不能匿名生图。
- 浏览器有两个独立入口：管理后台 `127.0.0.1:8001`，普通用户登录门户 `127.0.0.1:8003/portal/`；Node、Java 和管理工作台分别使用内部端口 8787、18080、8002。门户端口只向 Java 的认证与用户 API 代理，浏览器不接触 Node 令牌。
- 管理后台已统一为“海客电商生图”品牌：SVG 标识覆盖 favicon、登录页、侧栏和首页，默认使用海绿主题；若依上游许可与底层归属不变。
- 若依 BGE 任务中心除只读健康、任务、成品和鉴权图片外，只新增一个受控“补齐缺图”写入口；它复用原任务、原素材和原输出目录，不创建重复顶层任务。
- 权限保持最小化：`bge_viewer` 仅四项只读权限；`bge_operator` 增加作图与续跑但无系统管理；`bge_portal_user` 无菜单，仅经 `/portal-api` 访问示例与本人任务，Java 校验所有任务/成品操作归属。通用上传下载仅管理员可用，示例接口及 Springdoc、Swagger UI、Druid 默认关闭。
- 门户登录不再依赖 `bge_portal_user` 角色关联；所有未停用、未删除且能通过若依认证的用户都能进入工作台。注册与登录统一支持 6–32 位密码，修复了 21–32 位密码可注册但无法再次登录的问题；自助注册仍只分配无后台菜单的门户角色。
- 积分账本已启用：新账号一次性赠送 30 体验积分，1+2/2+3/3+4/5+8 套图按 1K、2K、4K 分别定价；提交冻结积分，零交付全退、部分交付按图片比例退款，原任务补图只收未结算部分。用户可查看余额、流水和提交充值申请，管理员可调账、审核充值和修改套餐价格，重复请求与重复审核均幂等保护。
- 后台只保留生图业务、账号管理和操作记录。账号固定为体验/标准/重点用户与只读/运营/超级管理员六级单选，角色页停用，超级管理员受保护。积分管理保留七页签和独立操作权限。
- MySQL 8.4 与 Redis 7.4 容器只映射回环地址。若依凭据位于仓库外 DPAPI 文件，数据库脚本拒绝 root 应用账号并已连续两次通过幂等验证。
- aiEcho 已增加单图双副本任务账本。已知任务号在网络、5xx、等待、下载、磁盘或 Sharp 故障后继续原任务；未知受理状态进入 `ambiguous` 并停止自动重提。
- 候选图在 `.part` 上完成同步、标准化和质量检查后才原子替换。标准 5+8 的并发、主备恢复、真流中断和单图返工均有故障注入测试；1+2、2+3、3+4 已有无网络全链路回归。
- 各工作台的进度、槽位和完成判定均读取任务实际主图/详情页数量；旧任务缺少字段时兼容显示历史 5+8。若依只读 DTO 同步保留该数量，轻量套图不会在代理后变回 13 张。
- 生图比例与数量、清晰度独立：默认主图 1:1/详情页 9:16，可选主图 3:4/详情页 9:16；清晰度为 `1k`、`2k`、`4k`，默认 `2k`；`720p` 仅兼容旧任务。
- 门户到 Node 的普通读取保持 8 秒超时，Multipart 作图/扩写写请求使用独立的 150 秒预算，覆盖当前最多两次 45 秒模型尝试及收尾时间，避免 Node 已接单而页面在 30 秒时误报失败。
- 正式生图工作流会在启动子进程前对当前图片供应商执行一次非生图连通性探测。网络不可达会以 `IMAGE_PROVIDER_UNAVAILABLE` 明确失败，不创建图片请求；失败/取消任务也不会再被任务板误标为“生成中”。
- 八项稳定性改造已落地：统一错误分类、1/3/10 分钟有限自动恢复、原任务缺图续跑、进程重启续跑、aiEcho 不确定受理防重复计费、整批失败冷却后单路探针、供应商熔断/可配置故障转移、按供应商/语言/清晰度统计成功率与 P95。等待与恢复状态对用户显示为后台恢复，预算耗尽后提供手动“继续生成/补齐缺图”。
- `tasks.json` 原子持久化恢复计划、尝试历史和熔断状态；优雅重启与强制终止后都会复用已有素材和成品继续，取消“等待自动恢复”会同时清除计时器。
- 本机联调覆盖权限、登录、隔离和恢复，未付费生图。
- GitHub 私有远端为 `hrbj18/BGE-ecommerce-auto-image-gen`。发布审计排除密钥、客户输入、历史成品、日志、缓存与依赖；公开发布仍需单独完成素材授权和许可证审查。

## 当前风险

- 真实生图速度、文字正确率和视觉质量仍受供应商影响。模拟测试只能证明流程合同，不能替代更多 SKU 的实图验收。
- 新增 8 种语言的机械鸭 1+2 真图均可解码且语言审核通过；5 组视觉问题仍需人工验收。
- 当前 5 路首发与 2 路恢复/返工是稳定基线，至少完成第二个不同类目 SKU 前不要上调。
- 本机当前只有主图片供应商凭据可用；故障转移会跳过未配置供应商，因此跨供应商容灾要在上线环境单独配置并用低成本单图验收。
- 当前未接支付供应商，充值由管理员审核；公开收费前须接入支付、回调、对账与退款。
- 若依固定提交的官方源码存在全树严格 `vue-tsc` 类型债。本次 BGE 新增代码使用独立严格配置通过，完整若依前端以生产构建通过为门禁。
- 账本尚未保存候选图 `candidateSha256`。替换后、完成状态落盘前崩溃时会用同一任务号保守重下载，供应商 POST 仍保持一次。
- 账本只保证单个 Node 进程内串行，不支持多个生成进程写同一成品目录。
- Windows 保留了 3306；MySQL 已无损迁移到回环端口 13306，旧容器和 SQL 备份保留，双入口一键启动已通过。
- 结论适用于本机若依和少量人员私网内测，不代表公网生产就绪。
- 1K 鼠标 10 平台 1+2 付费实测：30/30 生成及尺寸通过；视觉审核 26/30 自动通过，4 张需人工复核。Amazon 文字触边已修复。4K 1+2 已验证；2K、2+3、3+4 待实测。

## 下一步优先级

1. 让少量内部人员分别试用若依任务中心和 `8003/portal/`，确认普通用户注册、二次登录、体验积分、充值申请、我的任务/作品、等待自动恢复和手动补齐符合使用习惯；首个真实作图由使用者主动提交并单独确认费用和供应商结果。
2. 为上线环境配置经过验证的第二图片供应商后，执行一次主供应商 429/503 到备用供应商的低成本验收；没有备用凭据时继续依靠同供应商有限退避恢复。
3. 下一轮用第二个不同类目 SKU 复测首图耗时、429 比率、重启续跑、审核命中率和返工成本；轻量套餐单独记录 1+2、2+3、3+4 的耗时与人工评分。
4. 任何更高权限写操作、局域网扩网或公开发布都另立开发合同，并重新检查权限、端口、防火墙、素材授权和许可证。
