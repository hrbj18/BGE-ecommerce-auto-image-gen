# 当前状态

更新时间：2026-09-12

## 现在可确认

- 套图数量为受控预设：默认 `standard-5-8` 为 5+8，轻量预设为 1+2、2+3、3+4；失败图片只定向补齐。
- 平台风格与输出语言已经解耦。生图链路包含结构化分镜、逐图创意导演、紧凑提示词、生成前后审核和 `creative-plan.json` 追踪。
- 生成基线保持主图优先、5 路首发、`5>3>2>1` 退让，缺图恢复和视觉返工各为 2 路。首图落盘即可预览，任务 API 持久化真实进度、重试、限流和质检信息。
- 普通 React 工作台由 Node 监听 `0.0.0.0:8787`，局域网缺省关闭访问令牌；提交租约、幂等、上传限制、磁盘预检、取消、硬超时和原子存储已完成。
- 若依 3.9.2 固定源码位于 `admin/`，来源和许可证见 `admin/UPSTREAM.md`；BGE 扩展保持独立模块和页面。
- 若依统一入口为 `127.0.0.1:8001`，普通用户走 `/portal/`；Node、Java 和两个内部 React 服务分别使用 8787、18080、8002、8003，浏览器经同源代理访问且不接触 Node 令牌。Java 已避开本机 Docker/WinNAT 排除的 8080 端口段。
- 一键启动重建过期 Java JAR，且只刷新已核验后端。
- 若依 BGE 任务中心仍只提供健康、任务列表、任务详情、成品详情和鉴权图片五类 GET。页面按任务实际数量显示进度、错误摘要和缩略图，没有提交、取消、删除、重试、返工或下载入口。
- `bge_viewer` 只有四项 BGE 只读菜单/权限；`bge_operator` 只额外拥有“电商作图”及受保护作图桥接权限，不拥有系统管理权限。自助注册账号只得到无菜单的 `bge_portal_user`，只能经 `/portal-api` 访问精选案例和本人任务；任务、成品、图片、下载、取消及删除均在 Java 服务端按归属任务核验。通用上传下载仅管理员可用，官方示例用户接口已移除，Springdoc、Swagger UI 和 Druid 默认关闭。
- MySQL 8.4 与 Redis 7.4 容器只映射回环地址。若依凭据位于仓库外 DPAPI 文件，数据库脚本拒绝 root 应用账号并已连续两次通过幂等验证。
- Windows PowerShell 5.1 的原生管道曾把官方 UTF-8 初始化 SQL 转为本机代码页，导致旧数据库菜单文字保存为问号。初始化现改为原始字节复制到 MySQL 容器；既有库已通过隔离参考库只回填损坏的菜单、部门、角色、岗位、字典和默认昵称文本，未重置用户、密码、任务或素材。
- 9/9 从用户资源管理器复现凭据目录不存在；通过桌面进程恢复原 DPAPI 文件后后台启动成功。启动保存脱敏 `launcher-*.json`，区分缺失、拒绝访问、不可读及字段错误。恢复助手拒绝覆盖旧凭据。
- 首次启动会替换官方默认管理员密码，不覆盖人工密码；修改密码时同步更新当前 Windows 用户保护的 DPAPI 凭据。登录页不预填口令，复制脚本只写剪贴板。
- aiEcho 已增加单图双副本任务账本。已知任务号在网络、5xx、等待、下载、磁盘或 Sharp 故障后继续原任务；未知受理状态进入 `ambiguous` 并停止自动重提。
- 候选图在 `.part` 上完成同步、标准化和质量检查后才原子替换。标准 5+8 的并发、主备恢复、真流中断和单图返工均有故障注入测试；1+2、2+3、3+4 已有无网络全链路回归。
- 各工作台的进度、槽位和完成判定均读取任务实际主图/详情页数量；旧任务缺少字段时兼容显示历史 5+8。若依只读 DTO 同步保留该数量，轻量套图不会在代理后变回 13 张。
- 生图比例与数量、清晰度独立：默认主图 1:1/详情页 9:16，可选主图 3:4/详情页 9:16；清晰度为 `1k`、`2k`、`4k`，默认 `2k`；`720p` 仅兼容旧任务。
- 比例预设 ID 已贯通 Node、React、若依提交桥接和只读任务 DTO；历史任务缺少新字段时按已保存的 `suiteRatio` 恢复，无法识别才回退默认比例。
- 主页/管理弹层支持拖图；成品预览支持总览、逐张、长图适宽、按钮缩放和全屏，滚轮仅滚动；Chrome 验收通过。
- 门户参考图草稿按登录账号保存到浏览器 IndexedDB；刷新页面后可恢复图片、文件名、角色及 AI 扩写勾选状态，不会跨账号混用。提交等待期间先按当前套图显示真实槽位数量。
- 门户到 Node 的普通读取保持 8 秒超时，Multipart 作图/扩写写请求使用独立的 150 秒预算，覆盖当前最多两次 45 秒模型尝试及收尾时间，避免 Node 已接单而页面在 30 秒时误报失败。
- 正式生图工作流会在启动子进程前对当前图片供应商执行一次非生图连通性探测。网络不可达会以 `IMAGE_PROVIDER_UNAVAILABLE` 明确失败，不创建图片请求；失败/取消任务也不会再被任务板误标为“生成中”。
- 本机真实联调已验证 8001 管理登录入口、动态菜单、23 条既有任务、详情、鉴权缩略图、只读员作图拒绝、操作员作图允许、Cookie 桥接、Node 停机 503 与自动恢复；也已验证门户临时账号注册/登录、精选案例、本人任务和图片读取，以及另一账号对任务、成品、图片、下载、取消、删除的一律拒绝。临时账号和归属记录已删除，验证码配置已还原，没有调用真实付费生图。
- 门户/工作台由 Java 重组受控 Multipart 字段后转发 Node，并返回识图摘要；无效图片实测只触发本地校验，Node 保持健康且未调用供应商。
- GitHub 私有远端为 `hrbj18/BGE-ecommerce-auto-image-gen`。发布审计排除密钥、客户输入、历史成品、日志、缓存与依赖；公开发布仍需单独完成素材授权和许可证审查。

## 当前风险

- 真实生图速度、文字正确率和视觉质量仍受供应商影响。模拟测试只能证明流程合同，不能替代更多 SKU 的实图验收。
- 当前 5 路首发与 2 路恢复/返工是稳定基线，至少完成第二个不同类目 SKU 前不要上调。
- 若依固定提交的官方源码存在全树严格 `vue-tsc` 类型债。本次 BGE 新增代码使用独立严格配置通过，完整若依前端以生产构建通过为门禁。
- 账本尚未保存候选图 `candidateSha256`。替换后、完成状态落盘前崩溃时会用同一任务号保守重下载，供应商 POST 仍保持一次。
- 账本只保证单个 Node 进程内串行，不支持多个生成进程写同一成品目录。
- 当前结论适用于本机回环的若依管理和少量人员值守的私网内测，不代表公网生产就绪。
- 1+2 已完成 1K、4K 真图验证；4K 成品为 1 张 4096×4096 主图和 2 张 4096×7282 详情页，三图可解码，质检与压缩包通过。2K、2+3、3+4 待实测。

## 下一步优先级
