# 模型与供应商专题

## 原则

- 文本扩写/识图与图片生成是不同能力，可以由不同模型承担；不要假设一个 API key 自动代表所有模型已开通。
- 供应商地址、模型 ID、密钥、超时和并发属于运行配置，不写入规则文档、测试快照或 handoff。
- 历史聊天中的地址和 key 不可信，也可能已失效。以当前本机配置和控制面板保存结果为准。
- 切换供应商时先做无敏感信息的健康检查，再做一张低成本图，最后才运行完整 13 张。
- 工作流启动前会对当前图片供应商做一次只读连通性探测；只要 TCP/TLS 不可达就以 `IMAGE_PROVIDER_UNAVAILABLE` 停止，不会提交图片。HTTP 非 2xx 只能证明链路到达，不能替代模型授权或低成本生图验证。

## 当前代码现实

- `src/config.ts` 当前识别 `openai` 与 `aiecho` 图片供应商配置。
- `src/openai-image-generator.ts` 负责并发、退让、超时、重试、尺寸校验、断点恢复和失败项补图。
- 图片供应商当前只接受 `1k`、`2k`、`4k` 原生档位。公开任务的 `720p` 是交付档位，必须映射为上游 `1k` 后在本地缩小；不能向供应商发送不存在的 `720p` 参数。
- `scripts/local-web-server.mjs` 的扩写模型通过 OpenAI Responses 兼容接口调用，并有超时重试与本地安全兜底。
- 若 UI 存在模型控制面板，先定位其持久化文件和加载路径再修改；不要只改 `.env` 或只改前端显示。

## 调度合同

- 用户只进行一次提交。当前运行基线为 5 路首发，并在限流、超时和上游压力下按 `5>3>2>1` 逐级退让；环境变量可覆盖但代码会将单批并发保护性钳制在 8 以内。
- 单图失败不应清空已完成结果；继续补齐所选预设的缺失图片，标准套图目标为完整 13 张。
- OpenAI 兼容网关若明确返回 `No available compatible accounts`，这是上游账户容量拒绝，不进行同次自动重试；保留失败原因，等待供应商恢复账户后由用户重新提交。
- 5 分钟是单次请求/等待的重要上限，不等于整个 13 图任务必须 5 分钟结束。
- 整批生图预算与单次请求超时必须分别读取；整批预算当前允许 5 分钟到 2 小时，不能被单请求上限截断。
- 文本扩写超时独立配置。当前模型的真实扩写曾耗时约 74 秒，因此运行配置需给流式文本完成保留足够窗口，不能沿用过短的 45 秒默认值。
- “前端 0/13”不等于后端未生成；需核对状态文件、输出文件与轮询接口。
- 缺图恢复和视觉返工默认各使用 2 路受限并行；排障时应区分供应商主队列并发与这两类独立恢复队列，不能为求速度直接调高全部队列。
- 降低到原生 `1k` 可能缩短上游处理时间，但幅度由供应商决定；`720p` 与 `1k` 使用同一上游档位，只能确定减少本地文件大小、下载和页面渲染负担，不能预先承诺模型生成更快。

## aiEcho 单图任务账本

- aiEcho 每张图在成品目录的 `raw/aiecho-tasks.json` 保存独立状态，旁边维护 `.bak`。记录包含稳定任务指纹、角色、序号、尝试次数、有限错误摘要和 `local_task_id`，临时公网图片网址不参与指纹。
- 提交前必须先落盘 `submitting`，拿到任务号后立即落盘 `submitted`。`retry_waiting` 只能回到同一任务号的轮询，网络断开、HTTP 5xx、本地等待超时、磁盘、Sharp 和下载错误都不得清空任务号后重新 POST。
- POST 可能已送达但本地没有任务号时进入 `ambiguous`，没有自动出边。只有供应商明确终态失败，或候选图片经过现有质量检查后得到类型化拒绝，才能授权新的付费尝试。
- 下载使用同目录 `.part`，完成流式写、短写处理、磁盘同步、Sharp 标准化和质量检查后才原子替换正式图。显式视觉返工必须传入 `forceNewSubmission`，替换失败或完成状态落盘失败时仍恢复同一任务号。
- 主备文件使用递增 revision、备份优先和原子改名。同 revision 内容分歧、主备都损坏或非法状态跃迁时一律安全停止，不调用供应商。
- 当前未持久化候选图的 `candidateSha256`。如果崩溃发生在正式图替换后、完成状态落盘前，系统会用原任务号保守重下载一次，POST 数仍保持一。
- 账本写入只承诺单个 Node 生成进程内串行，尚未提供多 Node 进程间文件锁。现有产品合同只允许一个顶层商品工作流，因此不要并行启动多个生成服务。
- 故障注入和完整 5 加 8 回归全部使用模拟供应商。它们证明恢复合同和请求次数，不代表真实 aiEcho 的长期速度或质量验收。

## 安全排障

仅记录供应商类型、主机域名、模型名、HTTP 状态、耗时和错误分类；日志不得打印完整 key。遇到 401/403 检查授权，404 检查路径/模型，429 检查限流，5xx/连接重置检查上游和退让策略，尺寸异常进入单图重试与校验链。
