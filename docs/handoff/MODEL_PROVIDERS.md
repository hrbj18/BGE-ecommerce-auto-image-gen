# 模型与供应商专题

## 原则

- 文本扩写/识图与图片生成是不同能力，可以由不同模型承担；不要假设一个 API key 自动代表所有模型已开通。
- 供应商地址、模型 ID、密钥、超时和并发属于运行配置，不写入规则文档、测试快照或 handoff。
- 历史聊天中的地址和 key 不可信，也可能已失效。以当前本机配置和控制面板保存结果为准。
- 切换供应商时先做无敏感信息的健康检查，再做一张低成本图，最后才运行完整 13 张。

## 当前代码现实

- `src/config.ts` 当前识别 `openai` 与 `aiecho` 图片供应商配置。
- `src/openai-image-generator.ts` 负责并发、退让、超时、重试、尺寸校验、断点恢复和失败项补图。
- `scripts/local-web-server.mjs` 的扩写模型通过 OpenAI Responses 兼容接口调用，并有超时重试与本地安全兜底。
- 若 UI 存在模型控制面板，先定位其持久化文件和加载路径再修改；不要只改 `.env` 或只改前端显示。

## 调度合同

- 用户只进行一次提交。当前运行基线为 5 路首发，并在限流、超时和上游压力下按 `5>3>2>1` 逐级退让；环境变量可覆盖但代码会将单批并发保护性钳制在 8 以内。
- 单图失败不应清空已完成结果；继续补齐缺失图片，最终目标为完整 13 张。
- 5 分钟是单次请求/等待的重要上限，不等于整个 13 图任务必须 5 分钟结束。
- 整批生图预算与单次请求超时必须分别读取；整批预算当前允许 5 分钟到 2 小时，不能被单请求上限截断。
- 文本扩写超时独立配置。当前模型的真实扩写曾耗时约 74 秒，因此运行配置需给流式文本完成保留足够窗口，不能沿用过短的 45 秒默认值。
- “前端 0/13”不等于后端未生成；需核对状态文件、输出文件与轮询接口。
- 缺图恢复和视觉返工默认各使用 2 路受限并行；排障时应区分供应商主队列并发与这两类独立恢复队列，不能为求速度直接调高全部队列。

## 安全排障

仅记录供应商类型、主机域名、模型名、HTTP 状态、耗时和错误分类；日志不得打印完整 key。遇到 401/403 检查授权，404 检查路径/模型，429 检查限流，5xx/连接重置检查上游和退让策略，尺寸异常进入单图重试与校验链。
