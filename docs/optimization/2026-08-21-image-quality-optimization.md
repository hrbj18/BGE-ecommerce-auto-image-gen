## 2. 本次目标

本次优化必须优先提高“错误在付费生图前被发现”的能力，并确保逐图提示词中的关键合同不会因长度控制而丢失。

### P0：修复商品身份与可见展示名污染

1. 移除“任何膳食补充剂都自动命名为 Oregano Oil Supplement”的错误兜底。
2. 英文补充剂名称必须按可信证据区分：牛至油、滴剂/液体补充剂、胶囊/软胶囊、普通膳食补充剂。
3. 只有来源中明确出现 oregano/牛至油时才允许输出 `Oregano Oil Supplement`。
4. 视觉分析明确出现 NAD+、Shilajit、Resveratrol 或液体滴管，而没有牛至油证据时，不得输出 Oregano Oil。
5. 扩写质量门增加“可见展示名与可信产品/识图证据不一致”检查，错误名称应触发安全兜底或阻止进入生图。

验收：为喜来芝/NAD+ 滴剂输入生成的英文展示名不得包含 Oregano；真实牛至油软胶囊仍能得到 Oregano Oil Supplement。

### P0：修复逐图提示词硬截断

1. 禁止对完整提示词做无结构的 `slice` 截断。
2. 固定保留关键头部：当前图片任务、产品状态、场景、构图、镜头和可见证据。
3. 固定保留关键尾部：文案语言、精确文案白名单、画布、禁用项、不虚构条款。
4. 只压缩可选内容：视觉事实数量、卖点候选数量、全案变体规则、旧提示词补充片段。
5. 最终提示词仍不得超过 6000 字符，并且不得以半句或半段结束。

验收：使用超长视觉分析和旧提示词输入时，输出长度不超过 6000，且同时包含 `CURRENT FRAME MISSION`、`VISIBLE COPY CONTRACT`、精确文案、`CANVAS AND FINAL CHECK`、`Forbidden`、`Return the finished image only`。

### P1：统一审核器与新提示词合同

1. 设计审核必须能解析紧凑提示词中的弯引号或直引号英文文案白名单。
2. English 模式应准确判断语言规则、文案白名单和商品本体文字豁免，不因提示词格式升级产生假阴性。
3. 生成前审核应使用结构化分镜字段生成场景签名，避免把全局规则误判为重复场景。

验收：紧凑 English 提示词的 copy-lock、english-language-rule、english-visible-copy-clean 均可通过；中文和旧格式保持兼容。

### P1：补齐完整套图的非付费回归合同

1. 测试构造 5 主图 + 8 详情页，验证数量、角色、索引和逐图差异。
2. 验证 Amazon 与 English 只影响平台风格和可见文案，不降低品类分镜深度。
3. 验证每张提示词均保留产品事实、当前帧任务、精确文案和禁用项。
4. 不调用真实图片生成接口；使用单元测试和 stub 集成测试验证。

## 4. 实现设计

### 4.1 展示名解析

在 Web 扩写层建立“具体证据优先、通用品类后置”的英文展示名选择顺序：

1. 明确产品子类型和包装文字。
2. 明确剂型：liquid/dropper、capsule/softgel。
3. 明确一般品类：dietary supplement。
4. 无法得到具体名称时使用中性的 `Dietary Supplement` 或 `Liquid Dietary Supplement`，不得猜测原料。

质量门对展示名做反向校验：名称中的强身份词必须能在原始产品名或视觉分析中找到证据。

### 4.2 结构化提示词预算

把提示词拆为：

- required head：当前帧任务与执行单；
- optional context：产品事实、卖点候选、艺术方向、旧提示词中的品类物理逻辑；
- required tail：文案合同、画布和最终禁用项。

先计算 required head/tail，占用剩余预算后按优先级逐块加入 optional context；超长块按完整行压缩，绝不截断 required tail。

### 4.3 审核合同兼容

审核器应以结构化标记为主，兼容：

- `Use only these approved marketing lines: “...”`；
- 旧中文 `「...」`；
- 旧英文 exact-copy 格式。

审核失败必须给出“未找到文案合同”或“文案语言不合法”的真实原因，而不是笼统人工复核。
