# 单次开发指导文档：参考图拖拽上传

日期：2026-09-07

## 一、开发目标

在不改变现有生图、识图、AI 扩写、用户权限和上传接口的前提下，为“上传参考图”补齐一致、可预期的拖拽上传体验：

1. 主页“上传参考图”卡片可直接接收从 Windows 资源管理器拖入的一张或多张图片。
2. “管理产品参考图”弹层在空列表和已有图片两种状态下都可继续接收拖拽图片。
3. 两个入口复用同一套文件筛选、去重、数量上限、追加顺序和反馈逻辑。
4. 拖拽不会让浏览器直接打开本地图片，也不会覆盖已经选中的参考图。
5. 原有点击打开管理页、点击选择文件、预览、角色、排序和删除功能保持不变。

## 二、本次范围

### 必须完成

- 支持拖入单张及多张图片文件。
- 支持的类型沿用现有规则：浏览器识别为图片，或扩展名为 `png`、`jpg`、`jpeg`、`webp`、`gif`。
- 最多保留 5 张参考图；超过剩余容量时只追加可容纳的前几张，并明确反馈。
- 同一批次或与现有列表重复的文件不重复追加。重复判定使用文件名、大小和最后修改时间组合，不读取图片内容，也不增加上传等待。
- 拖入非图片、重复图片或超额图片时给出可理解的反馈。
- 拖拽经过可接收区域时显示明确高亮和“松开即可添加”的状态。
- 已满 5 张时仍拦截浏览器默认打开行为，并提示已达上限。
- 主页与管理弹层共享纯函数文件规划逻辑，避免两处规则漂移。

### 明确不做

- 不实现把整个文件夹本身拖入后递归遍历子目录；本轮只支持从文件夹中选中图片文件后拖入。
- 不修改后端 Multipart 接口、文件大小/像素限制或生图流程。
- 不增加云端上传、粘贴板上传、拍照入口或新的图片格式。
- 不重构当前大体页面布局，不改变既有视觉风格。
- 不发起真实识图、扩写或付费生图。

## 三、现状与设计判断

当前 `WorkbenchPage.addReferenceFiles` 已负责图片类型过滤和 5 张上限，但入口只有文件选择器：

- 主页 `ReferenceUploadCard` 只能点击打开参考图管理弹层。
- 管理弹层的“添加新图片”和空状态上传区只能点击选择文件。
- 页面没有处理 `dragenter`、`dragover`、`dragleave`、`drop`，因此不能提供投放反馈，也存在浏览器导航到本地文件的风险。
- 当前逻辑不区分无效、重复和超额文件，反馈不足。

本次采用“共享文件规划函数 + 两个轻量拖拽区域”的实现。文件规划函数只负责确定接收项与拒绝原因，React 组件只负责拖拽状态和调用已有追加入口。这样可独立测试规则，又不复制业务逻辑。

## 四、任务拆分

### 任务 1：建立统一文件规划规则

- 新增前端纯函数模块。
- 统一识别图片、计算稳定文件指纹、去除已有及批内重复项。
- 输出 `accepted`、`invalidCount`、`duplicateCount`、`overflowCount` 等可测试结果。
- 生成组合反馈文案，使拖拽和点击上传行为一致。

### 任务 2：接入主页拖拽

- 给主页上传卡片传入现有 `addReferenceFiles`。
- 让主虚线卡片成为 drop zone，但保留点击进入管理弹层的行为。
- 拖拽进入时显示遮罩/高亮；松开后直接追加图片，不强制打开弹层。
- 缩略图按钮保持只负责打开管理弹层，避免改变既有操作习惯。

### 任务 3：接入参考图管理弹层拖拽

- 让弹层内容区域在有图与无图时均能接收拖拽。
- 有图时显示非遮挡式投放提示，避免盖住删除、排序和角色选择。
- 空状态仍可点击选择文件，同时支持拖入。
- 预览大图弹层不接收上传，防止查看图片时误触发。

### 任务 4：状态、可访问性与视觉完善

- 使用拖拽深度计数避免子元素导致高亮闪烁。
- 仅对文件拖拽激活；普通文本拖拽不触发上传。
- 设置 `dropEffect=copy`，并在可投放区域提供清晰文本。
- 使用语义化状态文本和 `aria-live`，让反馈不只依赖颜色。
- 补齐桌面和窄屏样式，不遮挡已有控件。

### 任务 5：验证与交接

- 为纯函数补充 Node 单元测试。
- 运行新增测试、TypeScript 检查、前端生产构建和 handoff 审计。
- 启动本地页面，在真实浏览器分别验证主页和管理弹层的拖拽。
- 更新 `docs/handoff/WEB_APP.md` 和 `CURRENT_STATUS.md` 中的当前事实，不记录聊天流水。

## 五、开发顺序

1. 记录当前 Git 状态，仅增量修改本轮文件，不覆盖现有未提交改动。
2. 先实现并测试共享文件规划纯函数。
3. 把主页卡片接入拖拽状态，完成桌面和键盘点击回退。
4. 把管理弹层接入同一处理函数，验证有图、无图、已满三种状态。
5. 增加样式与提示文案，检查拖拽进入/离开不会闪烁。
6. 执行静态检查和生产构建。
7. 启动页面完成真实浏览器交互验收；发现问题时只在本轮范围内修正并复测。
8. 对照本文验收标准逐项给出通过、失败或未验证结论。

## 六、风险与处理

- **浏览器打开本地文件**：所有目标区域在文件拖拽经过和放下时调用 `preventDefault`；已满状态也必须拦截。
- **嵌套元素导致高亮闪烁**：使用 `dragenter`/`dragleave` 深度计数，并在 drop 后归零。
- **同一文件重复加入**：使用名称、大小、最后修改时间组合去重；这是快速交互去重，不声称是内容级去重。
- **超过 5 张**：只追加剩余容量，保持拖入顺序，并反馈忽略数量。
- **React 状态竞争**：最终接收计划在当前状态更新函数内计算，不依赖拖拽开始时的旧数量。
- **既有大规模未提交改动**：仅修改与本轮直接相关的前端、测试和交接文档，不格式化整个文件，不提交或清理其他改动。

## 七、测试方案

### 自动化测试

1. 单张合法图片可接收。
2. 多张合法图片保持原顺序。
3. 非图片被拒绝，合法图片仍可接收。
4. 与已有图片重复时跳过重复项。
5. 同一拖拽批次中的重复项只接收一次。
6. 当前 2/5 时拖入 4 张，只接收前 3 张并报告 1 张超额。
7. 当前 5/5 时不接收任何图片并报告超额。
8. 组合拒绝原因能够生成明确反馈文案。

### 构建与静态验证

- `node --test tests/reference-upload.test.ts`
- `pnpm run typecheck`
- `pnpm run frontend:build`
- `pnpm run handoff:audit`

### 浏览器验收

1. 在主页拖入一张图片，图片直接出现在主页缩略图中。
2. 再从资源管理器一次拖入多张图片，图片按拖入顺序追加。
3. 打开参考图管理弹层，拖入图片后卡片直接出现，弹层不关闭。
4. 拖入期间两处都有明显投放状态，离开或放下后状态恢复。
5. 拖入非图片、重复图片和超额图片时页面不跳转，已有图片不丢失，并显示反馈。
6. 点击上传、点击管理、图片预览、删除、角色和排序仍可正常使用。

## 八、验收标准

只有同时满足以下条件，本次优化才算完成：

- 主页和参考图管理弹层都能通过拖拽加入一张或多张图片。
- 两处使用同一套筛选、去重、5 张上限和反馈规则。
- 拖拽过程有可见状态，放下文件不会触发浏览器导航。
- 新图片追加而非覆盖，顺序稳定，第一张合法图片继续成为主参考图。
- 非图片、重复和超额场景不会破坏当前列表，并给出明确反馈。
- 原有点击选择文件及参考图管理功能没有回归。
- 新增单元测试全部通过；TypeScript 检查、前端生产构建、handoff 审计通过。
- 至少完成主页和管理弹层各一次真实浏览器拖拽验证，并保存可复核的测试结论。

如果因为运行环境无法模拟 Windows 文件拖拽，必须把该项标记为“未完成真实验收”，不能用静态检查代替。其他自动化和构建通过也不能将其表述为完整验收。

## 九、实施与验收结果

完成时间：2026-09-07

### 已实现

- 新增 `frontend/src/reference-upload.js` 和声明文件，集中处理图片识别、文件名/大小/最后修改时间快速去重、剩余容量和组合反馈。
- 主页上传卡片和参考图管理弹层接入同一 `useFileDropZone`，处理文件拖入深度、复制语义、默认导航拦截和高亮状态。
- 两处拖入都调用原有 `addReferenceFiles`；第一张合法图片继续成为主参考图，后续图片保持顺序追加。
- 原文件选择器、预览、角色、排序和删除功能保持不变；状态提示增加 `aria-live`。
- 新增 `scripts/smoke-reference-drag-upload.mjs`，通过本机 Chrome DevTools 原生 `Input.dispatchDragEvent` 携带真实本地文件路径完成可重复浏览器验收。

### 测试结果

- `node --test tests/reference-upload.test.ts`：7/7 通过。
- `pnpm run smoke:reference-drag`：主页拖拽、管理弹层拖拽、点击回退、重复拦截、批量超额和满额拦截全部通过；最终文件顺序符合预期。
- `pnpm run typecheck`：通过。
- `pnpm test`：181/181 通过，0 失败；测试均使用本地桩，没有调用真实付费生图。
- `pnpm run frontend:build`：通过。
- `pnpm run handoff:audit`：通过。
- `pnpm run release:audit`：通过，未发现发布集合泄密或异常膨胀。
- Chrome 用户页面目检：参考图管理弹层在 3 张图片时布局正常，添加、角色、排序、删除和完成按钮无重叠或遮挡。

### 开发中发现并解决的问题

1. 新纯函数缺少 TypeScript 声明导致 `tsc` 失败：已补充 `reference-upload.d.ts`。
2. 首版浏览器冒烟在 Chrome 结束前清理临时配置，触发 Windows `EBUSY`：已改为等待浏览器退出并有限重试清理。
3. React 热更新后测试缓存的 DOM 节点失效：已改为每次从当前 DOM 查询文件输入节点。
4. 新事实使 handoff 文件超过字符预算：已压缩重复表述并重新审计通过。

### 验收结论

本文第八节的功能、回归和真实浏览器拖拽标准全部满足。本轮没有实现整文件夹递归导入，也没有修改后端上传接口或发起模型/生图请求，符合冻结范围。
