# 单次开发指导文档：生图比例可选择

日期：2026-09-07

## 一、开发目标

把用户端当前禁用的“生图比例”改为可选择的受控参数，并让选择结果真实贯通扩写、任务持久化、分镜提示词、供应商请求、成品标准化、质量检查和历史任务展示，而不是只改变前端文字。

本轮只开放供应商与现有生成器已经支持、且不会破坏详情长图阅读方式的两种方案：

1. `ecommerce-standard`：主图 `1:1`，详情页 `9:16`。这是默认方案，也是旧任务兼容方案。
2. `portrait-main`：主图 `3:4`，详情页 `9:16`。用于需要更多纵向商品展示空间的场景。

套图数量和图片清晰度继续作为独立参数。选择 `1+2`、`2+3`、`3+4` 或 `5+8` 不应重置比例；选择比例也不应改变图片数量。详情页本轮不开放方图或 `3:4`，避免同时改变详情长图、移动端叙事和既有审核合同。

## 二、已验证现状

- 前端比例下拉框被禁用，显示值来自套图数量预设的 `suiteRatio`。
- 后端把比例从 `generationProfileId` 推导，浏览器不能独立提交比例。
- aiEcho 任务与账本已经接受 `1:1`、`3:4`、`9:16`，不需要修改第三方接口。
- 主图与详情页规格在生成器内大量以 `1:1` 和 `9:16` 初始化；应在统一出口按任务比例覆盖，避免逐品类修改和遗漏。
- 当前清晰度模块只保存固定的方图、竖版宽高；`3:4` 主图需要根据所选清晰度计算对应交付尺寸。
- 质量报告当前把所有主图都按方图审核，必须改为读取任务真实比例。

## 三、设计与实现方案

### 1. 独立比例预设

新增单一权威比例预设模块，提供列表、查找、严格解析和旧任务解析：

- 新任务只接受公开预设 ID。
- 旧任务没有预设 ID 时，根据已保存的 `suiteRatio` 恢复；无法识别时回退默认方案。
- 预设保存 `mainAspectRatio`、`detailAspectRatio`、展示名、摘要和说明。

套图数量预设中的旧 `suiteRatio` 字段暂时保留为兼容数据，但不再决定新任务比例。

### 2. 前端交互

- `/health` 返回可选比例预设。
- 产品表单增加 `imageAspectRatioProfileId`，默认 `ecommerce-standard`。
- 解锁“生图比例”下拉框，展示两种完整套图比例。
- 选择套图数量时保留比例；选择比例时保留数量和清晰度。
- AI 扩写快照、正式任务提交、历史提示词导入和顶部摘要都保留比例选择。
- 健康接口暂不可用时使用相同的前端安全回退列表。

### 3. Node API 与持久化

- `/api/jobs` 和 `/api/brief-expansions` 接收并严格校验 `imageAspectRatioProfileId`。
- 未传值按默认方案处理；未知 ID 返回 `400 IMAGE_ASPECT_RATIO_INVALID`。
- 结构化需求、扩写快照、任务记录、`任务信息.json`、状态和历史任务摘要保存预设 ID、标签、主图比例、详情比例与套图比例摘要。
- 重启加载旧任务时不得把历史比例错误改写为另一个方案。

### 4. 扩写、分镜与提示词

- 本地模板和模型扩写结果中的“套图比例”以当前比例预设为准。
- 扩写模型输出即使写回旧比例，标准化阶段也必须覆盖为用户选择值。
- 所有品类先生成原始规格，再在统一出口按角色写入任务实际比例。
- 创意导演和英文文案覆盖层使用规格中的真实比例，提示词必须明确 `1:1`、`3:4` 或 `9:16`。

### 5. 图片尺寸与质量检查

- 以清晰度宽度和真实宽高比计算交付尺寸，并保持高度为偶数。
- `3:4` 主图预期尺寸：`720x960`、`1024x1366`、`2048x2732`。
- 默认主图和详情页尺寸保持现状。
- 标准化、模拟生成、最小文件阈值、报告清单和设计审核读取实际比例。
- aiEcho 稳定任务指纹继续包含 `aspectRatio`，同一任务切换比例不会复用错误图片。

### 6. 若依桥接

若依只重组受控 Multipart 字段。将新字段加入白名单并增加 Java 测试，确保门户提交到 Node 时不会丢失比例。只读任务 DTO 同步返回比例预设 ID，旧记录可从 `suiteRatio` 恢复，保证从历史任务导入提示词时不丢失比例；不扩大若依权限和 API 范围。

## 四、开发顺序

1. 新增比例预设模块和单元测试。
2. 扩展清晰度尺寸计算，补齐 `3:4` 尺寸测试。
3. 扩展任务类型、文件夹任务读取和状态持久化。
4. 修改 Node 健康接口、扩写接口、任务接口及非法参数处理。
5. 修改生成规格统一覆盖、提示词与动态尺寸审核。
6. 修改 React 表单、快照、历史导入和提交。
7. 修改若依 Multipart 白名单和测试。
8. 更新 handoff 当前事实，运行聚焦、全量、构建和审计。

## 五、不在本轮范围

- 不开放浏览器输入任意宽高比。
- 不开放横图、`16:9`、`4:5` 或详情页方图。
- 不修改供应商地址、密钥、模型、并发、超时或重试策略。
- 不发起真实付费生图，不以模拟结果宣称真实供应商质量已验收。
- 不重写现有品类分镜和视觉规则。

## 六、验收标准

1. 用户端比例下拉框可操作，只显示“主图 1:1 / 详情页 9:16”和“主图 3:4 / 详情页 9:16”，默认前者。
2. 任意套图数量与任意公开清晰度均可和两个比例方案组合，切换其中一项不会改变另外两项。
3. 扩写请求与正式任务请求都提交比例预设 ID；Node 和若依桥接均保留该字段。
4. 使用 `portrait-main` 的本地模拟任务，主图规格、提示词、账本身份和成品尺寸均为 `3:4`，详情页仍为 `9:16`。
5. `720p`、`1k`、`2k` 的 `3:4` 主图分别交付 `720x960`、`1024x1366`、`2048x2732`；默认方案原尺寸测试不回归。
6. 本地/模型扩写的套图比例与选择一致，规划数量继续由套图数量预设决定。
7. 未带新字段的历史任务按默认比例正常读取；带有历史 `suiteRatio` 的任务能恢复匹配方案。
8. 未知比例预设返回 HTTP 400 和稳定错误码，不创建任务目录、不启动生图。
9. 聚焦测试、TypeScript 类型检查、React 生产构建、全量无付费测试、handoff 审计和发布审计全部通过。
10. 浏览器验证比例下拉可选，切换数量/清晰度后比例保持不变；本轮不点击“立即生成”。

只有以上标准全部满足，才能把本次开发标记为完成；真实供应商的速度和视觉质量仍需后续单独付费验收。
