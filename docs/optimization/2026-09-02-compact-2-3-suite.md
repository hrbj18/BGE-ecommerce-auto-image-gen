# 2 主图 + 3 详情页轻量套图开发指引

文档日期：2026-09-02

## 目标

在保留默认 `5 主图 + 8 详情页` 的前提下，新增一个受服务端校验的轻量预设：`2 主图 + 3 详情页`。它用于更快完成商品核心卖点验证，不改变现有 aiEcho 请求字段、模型、轮询、任务账本或并发退让策略。

## 范围与边界

- 预设 ID 固定为 `compact-2-3`，不能由浏览器提交任意图片数量。
- 主图保持 `1:1`，详情页保持 `9:16`。
- 两张主图分别承担商品首图、核心卖点证明；三张详情页依次承担核心主张、顾虑回应、卖点证明。
- 轻量套图是 5 屏交付，不是将 13 屏任务启动后再丢弃 8 屏。
- 默认仍为标准 `5+8`，历史任务无预设信息时按标准合同读取。
- 不发起真实生图，不改动供应商 API、密钥、模型、并发或超时配置。

## 实现路线

1. 建立唯一的生成预设表，供 Web 服务与 TypeScript 生成链路共用。
2. 将预设 ID、主图数、详情页数写入任务元数据、扩写快照与需求模板；后端拒绝未知预设。
3. 任务解析、复用检查、生成计划、提示词审核、进度、报告、总览文件与输出审计均从任务实际数量读取，不再硬编码详情页 `8`。
4. 为 `compact-2-3` 选择两张主图和三张详情页的专用屏序，确保最终输出索引连续为主图 `01-02`、详情页 `01-03`。
5. 工作台将“套图数量”改为可选预设；比例继续按预设展示，不能与数量脱钩篡改。
6. 增加无网络测试，覆盖默认兼容、伪造预设拒绝、2+3 的五帧计划、复用、报告、打包和 Web API 传递。

## 验收标准

- 未选择预设或历史任务缺失预设时，仍产生标准 5+8 行为。
- 选择 `compact-2-3` 后，任务元数据、扩写结果、任务 API 和前端历史记录均显示 2+3；它是核心卖点验证包，不承诺覆盖完整的 13 屏成交叙事。
- 生成器只计划 2 张主图与 3 张详情页，主图为 `1:1`，详情页为 `9:16`；不会提交其余 8 张图片任务。
- 质量审核、恢复检查、报告、拼接预览、压缩包和单图下载只期待这 5 张图。
- 伪造的预设 ID 返回明确 400，不能回退成隐性 5+8 或接受任意数量。
- 通过相关测试、类型检查、前端生产构建、handoff 审计和发布审计；不调用真实付费模型。
