# 1 主图 + 2 详情页与 3 主图 + 4 详情页套图开发指引

文档日期：2026-09-03

## 目标与边界

在既有 `standard-5-8` 与 `compact-2-3` 不变的前提下，新增服务端受控的 `compact-1-2` 和 `compact-3-4`。前者用于极速商品方向验证，后者用于包含商品首图、核心证明和真实使用的核心卖点验证。

- 两种方案固定为主图 `1:1`、详情页 `9:16`，浏览器不能自由填写数量或比例。
- 1+2 交付商品首图、核心主张、顾虑回应；3+4 在此基础上增加核心卖点证明、真实使用和详情页卖点证明。
- 不修改 aiEcho 请求、模型、密钥、账本、并发或超时配置；不调用真实付费模型。

## 实现步骤

1. 在唯一的生成预设表中登记 ID、展示名、数量和比例，并同步前端离线回退列表与 TypeScript 声明。
2. 让已选预设优先于任务中孤立的详情页数量，防止持久化任务在恢复时偏离受控方案。
3. 保持分镜按角色连续截取，验证 1+2 与 3+4 的主图/详情页索引、卖点覆盖和去重审计。
4. 通过本地 Web API 验证健康接口下发、未知预设拒绝、任务元数据和进度总数；通过本地生成模式验证实际计划、总览文件与提示词审核数量。

## 验收标准

- 前端与 `/health` 同时展示 `standard-5-8`、`compact-1-2`、`compact-2-3`、`compact-3-4`，默认仍是 5+8。
- 选择 1+2 后仅计划 1 张主图和 2 张详情页；选择 3+4 后仅计划 3 张主图和 4 张详情页；不会额外提交图片任务。
- 任务状态、审核预期数、恢复、报告、总览文件、下载清单均严格使用所选数量；包含冲突孤立数量的任务也以合法预设为准。
- 相关单元/API/本地生成测试、类型检查、前端构建、交接审计和发布审计通过；没有真实供应商调用。
