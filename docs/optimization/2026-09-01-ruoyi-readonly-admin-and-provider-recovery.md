## 一、本次开发目标

本次开发要交付一个可以在本机真实运行、可以登录、可以按权限查看生图任务和成品的若依后台管理系统，同时补齐 aiEcho 单图任务的持久化账本与重启恢复能力。

完成后，系统应形成下面这条清晰链路。

```text
管理员浏览器
  -> 若依 Vue3 TypeScript 管理页面
  -> 若依 Spring Boot 3 鉴权和只读代理
  -> 现有 Node 生图服务
  -> tasks.json、任务目录和成品目录
```

生图仍由现有 Node 程序负责。若依在本阶段只负责登录、角色、菜单、权限和只读展示。MySQL 保存若依自身的用户、角色和菜单，Redis 支撑若依登录会话。现有生图任务暂不迁移到 MySQL，也不引入新的 Redis 队列。

aiEcho 账本要独立记录每一张图片已经提交给供应商的任务号。程序重启后，如果供应商任务号已经保存，系统必须继续轮询原任务，不得再次提交同一张图片。图片下载要先写临时文件，校验通过后再原子替换正式文件。

## 二、为什么这两项必须一起完成

若依接入后，系统开始具备正式后台的形态，也会为后续多人使用、排队和运维提供入口。在扩大操作入口之前，现有供应商任务恢复必须先达到可控状态。

当前 aiEcho 流程在供应商任务整体完成后才把 `local_task_id` 写回 `prompts.json`。如果程序在提交成功后、最终图片完成前重启，轮询错误也可能进入现有重试流程并再次提交。原供应商任务可能仍在运行，因此会出现同一张图重复生成和重复付费的风险。下载又直接写入正式文件，进程中断时还可能留下半文件。

因此，本次先把任务观察入口和付费任务恢复基础一起建好。下一阶段再开放提交、取消、删除、多人队列或任务迁移，风险会明显更可控。

## 八、任务拆分与开发顺序

### 任务一  冻结开发合同

1. 完成本指导文档并在开发前冻结范围。
2. 记录当前 Git 状态、官方源码提交号和现有测试基线。
3. 建立独立工作分支。

完成标志是本文已经落盘，工作树原有内容没有被覆盖。

### 任务二  导入官方若依源码

1. 按固定提交号下载后端 `springboot3` 源码和前端 `typescript` 源码。
2. 把后端放入 `admin/backend`，前端放入 `admin/frontend`。
3. 排除上游 Git 元数据和不需要的旧前端。
4. 保留两套许可证并写入 `admin/UPSTREAM.md`。
5. 更新 `.gitignore`，忽略构建产物、日志、上传目录和本地秘密，同时保留不含秘密的前端环境模板。

### 任务三  实现 aiEcho 单图任务账本

1. 新增版本化账本格式，按单图保存稳定任务指纹、角色、序号、尝试次数、状态、`local_task_id`、时间和有限长度错误摘要。
2. 对账本写入进行进程内串行化，每个关键状态都采用临时文件、磁盘同步、原子改名和备份。
3. 加载时校验版本和结构。主文件损坏时读取备份，主文件和备份都损坏时停止付费路径并给出明确错误。
4. 提交前先写入 `submitting`，得到供应商任务号后立即写入 `submitted`，然后才进入轮询。
5. 重启看到已有任务号时继续轮询同一任务。轮询网络错误、供应商 5xx、本地等待超时和下载失败都不得重新提交。
6. 如果供应商可能已经受理，但本地没有拿到或保存任务号，则标记 `ambiguous` 并停止该图自动重提，避免重复扣费。
7. 只有供应商明确返回失败，或图片完成下载后明确未通过现有质量检查时，才允许创建下一次提交。
8. 下载先写 `${outputPath}.part`，落盘同步完成后再原子改名。重启时清理对应旧临时文件并从原任务号重新下载。
9. 最终图片已经存在且有效时，账本应自动修复为完成状态，不重新调用供应商。

稳定任务指纹要覆盖商品稳定输入、本地参考图内容哈希、图片角色和序号、宽高比、模型与分辨率。临时公网网址不得参与稳定指纹。

### 任务四  实现若依只读后端代理

1. 新建 `ruoyi-bge` Maven 模块并由 `ruoyi-admin` 引用。
2. 从 `BGE_ENGINE_BASE_URL` 读取固定上游地址，若依模式默认使用 `http://127.0.0.1:8787`。
3. 提供健康、任务列表、任务详情、成品详情和鉴权图片代理接口。
4. 使用若依权限注解保护每个接口。
5. 只允许 GET，模块内不提供生图提交、取消、删除、重试和下载业务接口。
6. 对任务号、成品号、目录段和文件名逐段校验，拒绝路径穿越、编码斜杠、控制字符和超长参数。
7. 返回专用 DTO，过滤本机绝对路径、素材路径、完整日志、完整提示词、令牌和来源地址。
8. 图片采用流式转发。上游超时、断开或返回非法内容时，返回可理解的固定错误，不影响若依登录和系统管理。

### 任务五  实现若依只读管理页面

1. 新增 TypeScript API 定义和任务中心页面。
2. 支持按商品名和状态筛选。
3. 展示任务状态、5 张主图和 8 张详情图进度、首图耗时和更新时间。
4. 详情区域展示安全裁剪后的错误信息和成品缩略图。
5. 活动任务按固定间隔刷新，页面隐藏或组件卸载后停止轮询。
6. 图片通过已鉴权 Blob 请求显示，并在释放组件时回收临时网址。
7. Node 不可用时显示明确提示，空任务显示正常空状态。
8. 页面不得出现任何写操作按钮。

### 任务六  初始化 MySQL、Redis、菜单和权限

1. 初始化脚本从仓库外 DPAPI 文件解密凭据，只注入子进程，禁止输出明文。
2. 导入官方若依核心 SQL 和 Quartz SQL。
3. 导入 BGE 只读菜单、权限和 `bge_viewer` 角色。
4. 初始化前检查 `ry-vue` 是否为空。发现已有业务表时停止，除非能证明只是本次可重复执行的结构。
5. 若依使用应用数据库用户，不使用 MySQL root。
6. Redis 使用独立数据库索引。
7. 数据库密码、Redis 密码和 JWT 密钥全部通过环境变量提供，提交配置中不得有可用默认秘密。
8. 首次验收只在本机开放。正式开放局域网前必须修改官方管理员密码并停用样例账号。

### 任务七  本机启动与运行边界

1. 为 Node 服务增加可配置监听地址，保留原有默认行为。
2. 若依模式把 Node 限制到 `127.0.0.1:8787`。
3. 若依后端和前端在首次验收阶段只监听回环地址。
4. 提供本机启动脚本和环境检查脚本，不打印任何秘密。
5. 启动失败时指出缺失依赖、端口占用或凭据缺失，不留下误导性的成功提示。

### 任务八  测试、修复和验收

先执行聚焦测试，再执行全量免费验证，最后进行本机集成验收。任何一条验收失败都要修复并重跑相关检查。真实付费生图不属于本次验收手段。

## 十一、停止条件与回退原则

遇到以下情况时停止扩大改动范围，优先保留可运行的现有系统并记录阻塞。

- 官方源码许可证或固定提交无法核实
- 初始化数据库时发现无法识别的既有业务表
- 需要修改现有 aiEcho 接口合同、质量规则或付费策略才能继续
- 无法在不暴露秘密的情况下启动若依
- 账本无法安全区分可恢复任务和可能已经提交的未知任务
- 回归测试显示现有 5 加 8 生成流程被破坏

所有新增能力应保持目录和模块隔离。若依故障时，现有 Node 和 React 工作台仍应可以独立运行。账本故障时，系统应停止可能产生费用的自动提交，并保留人工诊断信息。

## 十三、实现结果与验收记录

### 实现结果

本次目标已经按冻结范围实现。官方若依后端和 Vue3 TypeScript 前端以固定提交导入 `admin/`，Node 仍负责原有生成工作流，Java 只提供若依鉴权、角色权限和只读代理。React 工作台的局域网使用方式没有被改掉，若依管理入口独立运行在本机回环地址。

aiEcho 生成链增加了每张图独立的双副本任务账本和严格状态机。已取得任务号的图片在网络、5xx、等待、下载、磁盘或 Sharp 故障后继续原任务；受理状态不明且没有任务号时进入 `ambiguous`，自动路径停止。候选图只在 `.part` 上处理，完成磁盘同步、标准化和质量检查后才替换正式图。

### 保守边界

- 账本暂未持久化候选图哈希。正式图替换成功但完成状态尚未落盘时，会用同一个任务号保守重下载，不会再次提交付费任务。
- 账本写入只保证单个 Node 进程内串行。当前产品已有单顶层工作流合同，不允许多个 Node 生成进程同时写同一成品目录。
- 本轮真实验收证明本机若依登录、权限、只读数据、缩略图和降级恢复可用。模拟供应商测试证明本地故障不会重复 POST，但不能证明真实 aiEcho 在更多 SKU 和更长时间窗口中的速度与视觉质量。
