# 单次开发指导：后台启动凭据诊断

## 事实与目标

首次从代理命令环境测试成功；用户复测后，通过其项目资源管理器窗口的 Shell.Application 启动，稳定复现两份凭据 missing。账户 SID、会话、仓库及路径相同，原生文件打开返回 0x80070003（目录不存在），而代理进程可见并可解密凭据。这证明桌面进程缺少可见配置，非数据库密码错误；具体文件视图差异机制未确认。

已确认设计缺陷：恢复校验将缺文件、解密失败和结构错误合并；主入口吞掉导入失败原因且没有专属诊断记录。目标是统一校验，给出可复核原因，并实测原 CMD 入口重复启动成功。

## 实施步骤与范围

1. 增加独立凭据检查函数，区分 missing、unreadable、invalid-schema、ready；只返回安全状态供报告使用，凭据值仅在进程内使用。
2. 导入与恢复脚本复用校验；端口接受合法数字或数字字符串，秘密字段仍必须为非空 SecureString。已有容器的无效凭据继续保护性停止。
3. 主启动器保存每次运行的独立 JSON 报告，包括路径、账户、PowerShell 版本、凭据状态、失败脚本行号或成功入口；不写异常原文、配置值、环境变量全集、密码或令牌。启动失败显示报告路径。
4. 测试使用临时随机凭据，执行真实 PowerShell 5.1 校验；运行实际管理和门户 CMD，核验服务响应、进程复用和凭据字节未变。
5. 更新 handoff 并运行审计。不涉及供应商、生图、数据库账号、容器重建或 GitHub 上传。
6. 新证据补充：通过共享且 Git 忽略的受限临时目录，将原有 DPAPI 文件交给桌面进程。桌面端先验证两份文件都可解密，再将其复制到自身 LocalApplicationData，仅补缺且拒绝覆盖已有文件。完成后移除临时凭据，以项目资源管理器启动两个 CMD 验收；不以代理命令行成功代替桌面成功。

## 验收标准

- 缺失、损坏 XML、字段错误、合法数字端口与字符串端口均得到对应状态；空秘密与明文秘密被拒绝。
- 导入与恢复共享判定，不输出凭据内容；诊断报告不包含任何秘密字段值。
- 管理和用户 CMD 在本机退出码为 0，8001 页面及验证码正常；重复启动复用现有进程，不修改两份凭据。
- 项目启动合同回归、类型检查和 handoff 审计通过。
- 如未复现截图故障，交接明确写出此限制，不将诊断改进宣称为已确认的历史根因修复。

## 验收记录

- Windows PowerShell 5.1 凭据状态用例及启动/权限合同回归共 9/9 通过，TypeScript 检查通过。
- 两个实际 CMD 均退出 0，管理页、门户与同源验证码请求均 HTTP 200。两份凭据 SHA256 与服务进程记录在重复启动前后相同。
- 在现有容器下传入独立的不存在凭据路径，入口退出 1；报告准确标记 missing、保留另一份 ready，定位到恢复脚本行号；未创建凭据、重建容器或更改数据库。
- 后续已从用户现有项目资源管理器窗口复现：原生文件打开返回目录不存在，非密码解密失败。桌面进程校验并恢复原 DPAPI 文件后，同一路径启动报告为 ready，两份凭据均 ready；未更改任何密码、账号或容器。
- 验收方法修正：代理环境直接调用 CMD 的成功结果不足以证明资源管理器双击正常，桌面启动必须通过用户 Explorer 窗口发起并读取其独立报告。
