# 单次开发指导文档：成品图预览器体验升级

日期：2026-09-09

## 一、开发目标

解决主图总览、详情页总览和详情页完整长图在成品预览中被整体压缩、文字和画面无法看清的问题。预览器需要同时满足快速总览、逐张审阅和完整拼接图检查，并通过显式按钮完成缩放，不占用浏览器的滚轮或 `Ctrl + 滚轮` 行为。

## 二、范围与边界

本次允许修改：

- 普通 React 工作台及用户门户共用的成品图库和成品预览组件。
- 与预览器相关的样式、纯前端辅助逻辑和自动化测试。
- 当前状态及 Web 专题交接文档中与本次实现直接相关的条目。

本次不修改：

- 生图、识图、扩写、质检、任务并发和供应商 API。
- 成品文件格式、拼接算法、下载文件名和下载权限。
- 若依管理端只读任务中心的权限模型。
- 历史任务、用户素材和已完成成品。

## 三、现状与根因

- 成品 `ImagePreviewModal` 只提供下载、关闭和前后切换，没有缩放状态和查看模式。
- `.preview-canvas img` 同时限制最大宽度和最大高度。详情长图越长，为了完整适应视口就会被压得越窄。
- 主图总览、详情页总览、详情页长图和单张图片共用同一种显示策略，没有按资产类型选择合理默认值。
- 浏览器滚轮、触控板和 `Ctrl + 滚轮` 已有明确习惯，不应由成品预览器强制改为缩放。

## 四、设计方案

### 4.1 查看模式

对拼接资产提供三类能力：

1. `总览`：使用任务现有的单张成品组成响应式网格；主图只展示主图，详情图只展示详情图。
2. `逐张查看`：在同组单张成品中切换，显示当前序号和缩略图导航。
3. `拼接图` 或 `完整长图`：显示服务器已经生成的拼接文件，不在前端重新拼接。

默认行为：

- 主图总览、详情页总览默认进入 `总览`。
- 详情页完整长图默认进入 `完整长图`，并使用适应宽度。
- 普通单张图片默认使用适应窗口。

### 4.2 缩放和滚动

- 工具栏提供缩小、当前百分比、放大、适应窗口、适应宽度、实际尺寸和全屏预览。
- 缩放范围为 25% 至 300%，步长为 25%。
- 普通滚轮只滚动预览容器；不监听滚轮改变缩放，不拦截 `Ctrl + 滚轮`。
- 放大后由预览容器提供横向和纵向滚动；不依赖浏览器页面缩放。
- `+`、`-` 用于缩放，`0` 恢复当前资产的默认适应方式，`Esc` 关闭，左右方向键仅在逐张模式中切换同组图片。

### 4.3 布局和无障碍

- 工具栏在预览内容滚动时保持可见。
- 长图不设置最大高度，按可读宽度自然向下延伸。
- 总览网格可点击并可使用键盘进入逐张查看。
- 所有图标按钮具备中文可访问名称，当前模式使用按钮状态表达。
- 弹窗打开后锁定背景页面滚动，关闭后恢复；点击遮罩和 `Esc` 均可关闭。
- 窄屏下工具栏允许换行，导航按钮不能遮挡主要画面。

## 五、任务拆分与开发步骤

1. 建立本次独立开发分支，确认工作区没有未提交改动。
2. 提取并实现资产分组、默认查看模式和缩放计算等纯函数，使规则可单独测试。
3. 扩展成品预览组件，使其接收全部成品资产并提供总览、逐张和拼接图模式。
4. 实现显式缩放工具栏、适应窗口、适应宽度、实际尺寸和全屏状态。
5. 调整预览 CSS，取消长图最大高度限制，建立独立滚动容器、响应式网格和窄屏布局。
6. 补充键盘、遮罩关闭、背景滚动锁定和按钮可访问状态。
7. 增加前端规则测试或等价的无网络合同测试，覆盖资产分组、默认模式和缩放边界。
8. 运行类型检查、前端生产构建、项目快速验证、handoff 审计和发布审计。
9. 启动本地页面，使用现有雨伞成品或项目预览数据完成桌面与窄屏浏览器验收，不发起付费生图。
10. 根据实际结果修复问题，更新当前状态和 Web 专题文档。

## 六、测试计划

### 6.1 自动化与静态测试

- 资产组映射：主图总览只关联主图，详情总览和详情长图只关联详情图。
- 默认模式：总览进入网格、详情长图进入适应宽度、普通图片进入适应窗口。
- 缩放边界：不能低于 25%，不能高于 300%，步长保持 25%。
- 运行 `pnpm run typecheck`。
- 运行 `pnpm run frontend:build`。
- 运行本次新增的聚焦测试。
- 运行 `pnpm run verify:quick`、`pnpm run handoff:audit` 和 `pnpm run release:audit`。

### 6.2 浏览器验收

- 打开含主图、详情页、总览和详情长图的已完成作品。
- 验证主图总览和详情总览默认以网格呈现，点击任意单图进入逐张查看。
- 验证详情完整长图默认按宽度展示，文字可读，并可在弹窗内连续向下滚动。
- 验证缩小、放大、适应窗口、适应宽度和实际尺寸均有可见效果。
- 验证滚轮不会触发自定义缩放，`Ctrl + 滚轮` 不被组件拦截。
- 验证 `Esc`、遮罩关闭、键盘缩放和逐张切换。
- 验证门户鉴权图片仍能显示，下载当前图仍可使用。
- 验证桌面宽屏和窄屏下无按钮遮挡、横向页面溢出或无法关闭的问题。

## 七、验收标准

本次目标只有在以下项目全部满足时才算完成：

1. 5+8 任务的 8 张详情图不再只能以一条不可读的细长拼图查看；用户可以总览并逐张放大审阅。
2. `详情页完整长图` 打开后默认适应宽度，不受视口高度压缩，可以在弹窗内部纵向滚动到底。
3. 单张、总览和长图均有清晰可见的缩放控制，支持 25% 至 300%、适应窗口、适应宽度和实际尺寸。
4. 成品预览器不使用滚轮或 `Ctrl + 滚轮` 执行缩放；普通滚轮仍可自然滚动长图。
5. 总览图关联的单图数量与任务实际套图数量一致，兼容 1+2、2+3、3+4 和 5+8。
6. `Esc`、遮罩关闭、左右切换、`+`、`-`、`0` 均按约定工作，按钮有可访问名称和当前状态。
7. 桌面和窄屏页面没有内容溢出、工具栏遮挡、导航按钮覆盖核心图片或无法退出的问题。
8. 门户鉴权加载、当前图下载、历史作品和既有单图预览没有回归。
9. 聚焦测试、TypeScript 检查、前端生产构建、快速验证、handoff 审计和发布审计通过。
10. 浏览器使用现有成品完成真实预览验收；若无法获得某类现有成品，必须明确标注该项未做真实验收，不能用静态测试冒充完成。

## 八、停止与回滚条件

- 如果实现需要改变成品 API、下载权限或拼接文件结构，停止并重新评估，不在本次范围内扩张。
- 如果发现工作区存在其他任务未提交且与 `frontend/src/App.jsx`、`frontend/src/styles.css` 或交接文档重叠，停止修改并先处理并发冲突。
- 所有改动保持在独立分支中；出现回归时可回退本次分支，不覆盖主分支。
